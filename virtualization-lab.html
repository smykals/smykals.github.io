01 / Purpose & Ownership

Give each workload a clear home.

I use this independent lab to develop infrastructure administration, storage, remote-access, and local AI skills. The current environment separates these functions across dedicated physical systems.

My role: I build and administer the lab, connect its physical and virtual components, investigate failures, and document what I learn. It is a personal learning environment, rather than an employer production deployment.

03 / Workloads

Physical placement and virtual dependencies.

Jump serverDedicated hardware runs Proxmox, with Windows 11 as a virtual machine for jump and administrative work. The physical host, hypervisor, guest firmware, and drivers form separate administration layers.
NAS / storageTrueNAS runs on its own hardware and connects to physical hard disks. The host has two physical Ethernet connections using a bridge. This description does not assume bonding, failover, or a particular disk-passthrough implementation.
VPN / remote accessA separate physical host runs WireGuard and Tailscale. Keeping its placement explicit helps document the remote-access dependency.
Local AIDedicated hardware runs Ollama with Open WebUI. The user interface and model-serving layer are distinct parts of this workload.

05 / Documented Troubleshooting

Identify the layer before changing the system.

Two documented examples focus on guest storage drivers and installation-media compatibility.

Windows Setup could not see the disk

Symptom
Windows Setup showed no drives.
Evidence
The virtual disk existed in Proxmox and was attached to the VM.
Fix
Mounted the VirtIO driver ISO and loaded the Windows 11 x64 SCSI driver from vioscsi\w11\amd64.
Verification
The disk appeared after the driver loaded.

Void would not boot from the first ISO

Symptom
The first downloaded installation image would not boot in this VM.
Evidence
The image was an Asahi build, incompatible with the x86_64 VM.
Fix
Selected the x86_64 glibc base image and installed the minimal guest.
Verification
The build concluded with a working Void Linux VM.
06 / Lessons & Supporting Records

Understand the dependencies between systems.

A detected virtual device still needs a compatible guest driver. Dedicated workload hardware makes placement clear, while each system retains its own storage, network, and application dependencies.

The VM journal provides specific symptoms and fixes. Separate NAS and AI journal entries document related work; their earlier configurations should be read in the context of when they were written.
