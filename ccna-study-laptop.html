Project 04 / Study Workstation

CCNA Study Laptop

A dedicated Linux-based networking workstation configured for CCNA study, packet analysis, terminal-based networking tools, documentation, troubleshooting, and hands-on lab work.

01 / Overview

A purpose-built networking workstation.

Rather than using a general-purpose computer for certification study, I repurposed a business-class laptop into a dedicated networking workstation.

The system provides a Linux environment for studying network concepts, analyzing traffic, accessing Cisco equipment, working with virtual labs, documenting configurations, and practicing structured troubleshooting.

02 / Operating System

Parrot OS.

The workstation runs Parrot OS, providing a Linux-based environment with access to networking, packet analysis, administration, scripting, and troubleshooting utilities.

The objective is not to turn CCNA preparation into a security project. Instead, Linux provides visibility into network behavior and exposes tools that complement Cisco configuration work.

Parrot OS Linux Cisco Wireshark tcpdump Nmap SSH Python Packet Analysis CLI
03 / Purpose

Study, test, observe, troubleshoot.

CCNA Study Maintain Cisco study material, documentation, notes, and networking references in a dedicated environment.
Packet Analysis Use Wireshark and tcpdump to observe traffic and reinforce how protocols behave on a live network.
Network Testing Use Linux networking utilities to validate addressing, connectivity, routes, DNS, ports, and services.
Cisco Administration Connect to physical network equipment using secure terminal-based management tools.
Documentation Capture configurations, diagrams, troubleshooting notes, commands, and lessons learned from each lab.
Automation Provide a Linux and Python environment for future network automation and scripting exercises.

05 / Troubleshooting

Use multiple perspectives on the same problem.

One advantage of the workstation is the ability to compare what the network infrastructure reports with what an endpoint actually experiences.

Cisco CLI output can show the state of the infrastructure while Linux tools provide another view of addressing, reachability, DNS resolution, route selection, open connections, and packet flow.

01 Verify local interface state
02 Validate IP addressing and subnet information
03 Test local and remote reachability
04 Examine the traffic path
05 Validate DNS and required services
06 Compare endpoint behavior with network-device state
07 Capture packets when additional evidence is required
08 Document the cause and resolution

07 / Current Development

The workstation evolves with the curriculum.

  • Build a reusable library of networking and troubleshooting commands
  • Expand packet-capture analysis exercises
  • Develop Python network automation fundamentals
  • Add additional Cisco lab tooling as needed
  • Integrate further with physical Cisco equipment
  • Document repeatable troubleshooting scenarios
  • Use controlled failures for timed troubleshooting practice
  • Continue building Linux administration skills alongside networking
08 / Takeaway

The workstation is part of the lab.

Building a dedicated study system turned the laptop itself into part of the learning environment. It provides a consistent place to configure, observe, test, document, and troubleshoot networks rather than limiting study to reading or memorizing commands.

The result is a platform that supports CCNA preparation today while also providing a foundation for Linux administration, packet analysis, scripting, automation, and more advanced network engineering work.
